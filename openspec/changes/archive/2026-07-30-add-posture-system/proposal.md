## Why

当前战斗已经处理 HP 伤害、受击反应、格挡和破防，但缺少让进攻压力与防守策略持续关联的资源。参考《只狼》的架势系统为 Player 和 NPC 增加第二条战斗轴：命中与格挡会积累架势，恢复速度受剩余 HP 影响，架势满时产生强制破绽。

## What Changes

- 为 Player 和 NPC 战斗角色增加可配置架势值，初始为零且不超过最大值。
- 有效攻击命中或被成功格挡时，根据攻击/战斗配置增加防守方架势，而不是由 UI 计算。
- 存活角色随时间恢复架势；恢复速率随 HP 比例单调增加，HP 越高恢复越快。
- 架势达到最大值时强制进入专用 `PostureBroken` 状态，并在破势开始时把架势重置为零。
- 在线模式下由 Server 权威处理架势变化与破势转换，并向远端观察者提供可纠正、可延迟绑定的绝对架势状态。
- 在本地 Player HUD 增加屏幕下方居中的独立黄色架势条：采用最终紧凑尺寸并从中心向两侧填充，零架势时隐藏，满架势归零时放大强调一秒后隐藏。
- 非本地 Player/NPC 的唯一世界 UI 继续显示最终紧凑尺寸、从中心向两侧填充的黄色架势条，并复用锁定可见性。
- 所有架势条达到满值/进入破势时显示红色边框一秒，且纯 Client 复用权威破势边沿触发。
- 更新项目需求、路线/进度和验证文档中的能力与验收矩阵。

## Capabilities

### New Capabilities

- `posture-system`：定义 Player/NPC 的架势所有权、增长、受 HP 影响的恢复、破势行为、网络权威、UI 表现和验证要求。

### Modified Capabilities

无。当前没有已归档的主能力规格定义战斗属性或 UI 行为；项目文档更新作为本 change 的交付任务处理。

## Impact

- 角色战斗运行时：健康/架势所有权、命中与格挡结算、死亡/复活、配置和事件。
- 状态机：Player/NPC 新增破势状态、打断和转换规则。
- 网络：快照或等价协议同步绝对架势，并传播破势动作/状态。
- 表现：在 Reaction Layer 使用现有 `rig_Collide` 资产表现破势，但动画不是逻辑状态。
- UI/预制体：`InGameHud` 在屏幕下方居中显示按架势值显隐的本地架势条并提供崩防强调；`NpcHealthBar` 显示紧凑世界架势条；所有架势填充均从中心向两侧对称扩展，两者共用一秒红框反馈，锁定目标继续复用世界 UI。
- 数据资产：默认最大架势、增长倍率、恢复延迟/速率、HP 影响和破势持续时间。
- 文档与验证：能力需求、Phase G0/G 进度和 Offline/Host/Client 架势用例。
- 不增加外部包依赖。
